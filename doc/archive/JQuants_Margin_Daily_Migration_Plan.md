### 1.3 検索条件

- `code`、`date`、`published_date` のいずれかの指定が必要。
- 銘柄別の申込日期間検索は `code + from + to`。
- `published_date` と `date / from / to` の併用は不可で、400エラーとなる。
- `code + published_date` は可能。
- 公表日が収録されていない旧系列は、公表日検索では返らない。
- 第1段階の取得窓は両端込み90暦日とする。具体的な上端と理由は第6章で定める。

## 3. 日次化で壊れる前提と、壊れていない前提

| 前提 | 判定・変更方針 |
|---|---|
| 隣接する行が一定の1週間を表す | 壊れる。同じAPI結果に週次・日次が混在するため、系列種別と実営業日差を確認する。 |
| 6行前なら5週間前 | 成立しない。旧週次にも非提供週があり、空売り報告には複数主体の行もある。 |
| 最新収集なら信用残も最新 | 成立しない。完了銘柄のスキップ、価格日で止まる窓、`update_daily` の対象外がある。 |
| 信用残に公表日がない | 旧系列では成立するが、日次系列では成立しない。 |
| 信用倍率＝買残株数÷売残株数 | 定義は維持できる。ゼロ除算・欠測の区別も維持する。 |
| 倍率3／5／10／20／50という水準 | 同じ比率尺度として比較可能。ただし投資判断上の有効性まで保証されるわけではない。 |
| 信用売残と規制上の空売り報告は交換可能 | 公式上成立しない。別データとして維持する。 |
| 未公表データを過去判断へ入れない | 引き続き必須。日次化で緩めない。 |

1営業日変化を既存閾値へ渡すと、数週間では大きく増えた残高でも毎日の増加が5%以下なら安全性の満点帯に入りやすくなる。一方、25／50／100%の投機性条件の発生頻度も変わる。比較期間を変更すると閾値の意味が変わるため、既存増減率閾値を流用しない。

## 4. 採用する指標の定義、空になる条件、採点へ渡す時期

### 4.1 第1段階の診断項目

数値の空欄はJSONでは `null`、CSVでは空欄とし、計算状態・理由を併記する。API原値は加工せず保持する。

| 指標 | 定義 | 主な空欄条件 |
|---|---|---|
| 信用倍率 `margin_ratio` | `LongVol / ShrtVol` | 売残0、対象外、不正値、未取得・未公表。 |
| 信用買残・売残 | `LongVol`、`ShrtVol` | 対象行が利用不可。 |
| 一般・制度信用売残 | `ShrtNegVol`、`ShrtStdVol` | 該当値が利用不可。 |
| 信用売残金額 | `ShrtVal` のAPI原値 | 旧週次、欠測、契約不整合。 |
| 一般売残比率 | `100 × ShrtNegVol / ShrtVol` | 売残0、内訳不明・不正。 |
| 金額比・監査用 | `LongVal / ShrtVal` | 売残金額0、旧週次、金額不明。 |
| 買残・売残の1／5／20営業日変化率 | 下記の式 | 履歴不足、基準値0、企業行動・時点の確認不足等。 |
| 週次から日次への橋渡し変化 | 最後に確認できた週次行と9月25日日次行の増減率 | 両端不足、基準値0、企業行動未確認。 |
| 信用売残／20日平均出来高 | `ShrtVol(t) / mean(Vo[t−19…t])` | 同期間の出来高不足、平均0、株数基準不明。 |
| 鮮度 | 申込日からの営業日数、公表日からの暦日数、取得日時 | 日付またはカレンダー不明。 |

金額6列はすべて保存する。単位確認までは円換算・価格からの逆算をせず、表示する場合は「API原値・単位未確認」と付記する。

金額比が株数比と異なる情報を持つかは評価方法に依存する。同一単価評価なら一致するため、独立した需給評価には採用せず監査列に限定する。評価方法をサンプルから推測しない。

「信用売残／20日平均出来高」は本書独自の参考日数であり、実際の返済所要日数や他機関の公式回転日数として表示しない。分母は信用残Dateにそろう20営業日の出来高とし、古い価格日で終わる平均出来高を流用しない。

### 4.2 状態の定義

取得状態、対象状態、倍率状態、指標ごとの計算状態は分離する。

- 売残正・買残非負：有限倍率。買残0なら数値上0だが安全認定には使わない。
- 売残0・買残正：`zero_short_balance`、倍率は空欄。
- 両方0：`both_zero`、倍率は空欄。
- `IssType=3`：`not_applicable`。原値は保存し、派生評価は空欄とする。これは第1段階の適用範囲判断であり、公式が残高ゼロを保証するという意味ではない。
- `IssType` 不明：`issue_type_unknown`。
- 正常取得・行なし：`no_rows`。
- 未取得・権限不足・取得失敗・スキーマ未対応・未公表：それぞれ識別可能な状態を保存する。
- 不正値、矛盾する同日行、企業行動未確認、基準値0、窓不足：指標別の理由を保存する。

最新行が不正・対象外の場合に、古い正常行を現在値として黙って復活させない。古い値を表示するなら「前回観測」の日付・状態付きの別枠とする。

### 4.3 営業日変化の計算契約

残高Xは買残または売残、Nは1・5・20とする。

`変化率_N(X,t) = 100 × (X(t) / X(t−N営業日) − 1)`

数値を出すには以下をすべて満たすこと。

1. 両端が日次系列で、東証現物の営業日差が正確にN日である。
2. 窓内のN＋1営業日の信用行がそろい、同じコードで、`IssType` が1または2のまま連続している。
3. 基準値は正、終点値は非負。基準値0は、終点も0であっても空欄とする。正の基準値から終点0への変化は−100%となる。
4. 使用する各行・各版が情報締切までに利用可能である。
5. `(t−N営業日, t]` の企業行動を確認でき、株数基準を変えるイベントがない。

第1段階では信用株数の調整系列を作らない。既存価格キャッシュの `ExRT`・`AdjFactor` 等を確認し、分割・併合・ライツ、説明できない係数、確認履歴不足があれば無効とする。価格キャッシュが古く対象期間を覆わない場合も `corporate_action_unverified` とする。

週次値の前方補完、近い日付への置換、営業日不足を行数で埋める処理は行わない。参考日数の出来高窓にも、同様の株数基準・履歴確認を適用する。

### 4.4 移行時の期間と最短日

9月21～23日は休業日のため、9月18日から25日は **7暦日・2営業日**（9月24日・25日）。根拠は [JPX営業日カレンダー](https://www.jpx.co.jp/corporate/about-jpx/calendar/) 。隣接1期間を1営業日と解釈すると、2営業日の変化を1営業日と誤る。

橋渡し変化は通常の1／5／20営業日変化と別列にし、両端日と実営業日数を必ず付ける。9月18日の行が取得できず、さらに古い週次行が起点となる場合は、その実際の期間を表示する。固定で2営業日と埋めない。企業行動確認と正の基準値の条件も適用する。

| 日次同士の指標 | 最短の終点Date | 翌営業日配信規則による最短公表日 |
|---|---|---|
| 5営業日変化 | 2026-10-02 | 2026-10-05 |
| 20営業日変化 | 2026-10-26 | 2026-10-27 |

起点はいずれも9月25日。20営業日の計算では10月12日の休業も除外する。公表日は規則からの算定値であり、実際の配信を確認した値ではない。実取得・必要行・企業行動確認がそろって初めて利用可能となる。それ以前や確認不足時の空欄は正常である。

### 4.5 採点への接続時期

第1段階では、全診断項目を安全性点・投機性点・旧総合点・推奨点・新規買い可否へ渡さない。既存 `short_selling_change_rate` は空欄を維持し、新しい期間別診断列を使用する。

水準指標を参考点へ接続するかは実データの時点監査後に別決定とする。増減率は期間別分布を確認して新しい閾値を決める。1営業日変化と橋渡し変化は採点入力にしない。欠測に安全側の加点を与えず、信用倍率単独の売買規則も追加しない。

## 5. 時点ルール

### 5.1 保存する時点

| 項目 | 意味 |
|---|---|
| `price_asof_date` | 参照する価格の共通基準日。 |
| `information_cutoff` | 当該診断で利用できる情報の締切日時。 |
| `Date` | 信用残の申込日・残高基準日。 |
| `PubDate` | 信用残の公表日。 |
| `collected_at` | 取得処理が完了した日時。 |
| `first_observed_at` | 当該行の当該内容版を初めて保存できた日時。 |
| `availability_basis` | 利用可能時刻の根拠。 |

日時はタイムゾーン付きJSTで保存する。診断用snapshotは元スクリーニングのsnapshotと情報締切を別に持つ。

### 5.2 現在の診断

第1段階では保存した行の版について `first_observed_at <= information_cutoff` を要求する。日次行ではさらに `Date < PubDate <= information_cutoffの日付` を確認する。Dateは取引所営業日として確認する。

公表日しかなくても、その日に実際に取得できた証拠があれば、取得確認時刻以後の現在診断には使用できる。その時刻を公表時刻として記録してはならない。

旧週次はPubDateがないため、保存された取得確認時刻を保守的な利用可能時刻とする。推定の金曜日や火曜日を埋めない。過去bundleの取得時刻を利用する場合も、それが当該原データを保存した証拠であることを条件とし、真の初回観測だと推定しない。

鮮度は申込日・公表日・取得時刻を分けて出す。Standardの配信時刻が未確認の間、当日の想定申込日がまだ観測されないことだけで障害・安全・危険と判定しない。銘柄全体の取得日時が新しくても、信用残が更新済みとはみなさない。

### 5.3 価格日が2026-09-11のままの場合

9月25日以降の信用残を使用できるのは、次の条件を満たす現在の信用診断とする。

- `price_asof_date=2026-09-11` を明示し、診断締切の日付以前であることを確認する。
- 診断の `information_cutoff` は当該版の取得確認時刻以後とする。
- 当該行のDate・PubDateが前項の条件を満たす。
- `Date > price_asof_date` を `margin_after_price_asof=true` と表示する。
- 9月11日の順位・推奨点・新規買い可否を再計算しない。
- 同期した出来高・企業行動履歴がなければ参考日数・変化率を空欄とする。

「9月11日価格を参照した、9月28日現在の信用観測」には使用できるが、「9月11日当時の判断」には使用できない。信用診断の締切更新で、元スクリーニングの締切まで更新したことにしない。

### 5.4 過去順位と訂正

- 公表日だけの行を当日00:00から既知だったことにしない。
- 当日取得の保存証拠があれば、その取得時刻以後だけ利用できる。
- 公表日だけから保守的な利用時刻を置くなら翌暦日00:00以後とする。ただし、それだけでは当時のデータ版を証明できず、過去順位への採用条件を満たさない。
- 現在取得した過去データしかなく、当時利用できた版を確認できなければ、過去順位の入力から除外する。
- 同じコード・Dateでも訂正で内容が変われば別版とし、旧版の `first_observed_at` を継承しない。
- 使用版、時点根拠、原データ参照と `pit_quality` を記録する。

信用専用の時点判定を用意し、財務等にも使われる既存 `published_at` の挙動を一括変更しない。

## 6. 段階導入

### 6.1 現在の段階：ドキュメント化のみ

本書保存で今回の作業を終了する。コードの取得停止はそのままとし、日次データを再取得するための実装・テストは行わない。実装開始は別途の作業指示による。本書の状態を「実装済み」「実データ検証済み」に変更するには、それぞれの実施記録が必要である。

### 6.2 将来の第1段階で触ってよい範囲

以下は将来実装の見積もり対象であり、現在存在する機能・CLIではない。

1. **新旧アダプタ**  
   Dateによる系列区分、必須項目・型・コード・銘柄区分・時点を検証する。旧保存データに存在しない追加項目は旧契約として空欄へ正規化する。日次行の必須キー欠落はスキーマ未対応として隔離する。日次契約に反するnull・不正値は理由付きで利用不可とする。未知の追加列は原値保存する。
2. **取得停止の置換**  
   `collect` の日付だけによる停止を検証付きアダプタへ置き換える。検証不能な応答は原値保存・診断空欄とし、価格・財務の完了判定を変更しない。通常collectの価格日固定・全体収集規則は維持する。
3. **独立した信用更新入口**  
   収集フェーズ `margin_refresh` を新設する。元snapshotを指定し、その普通株を対象とする。価格・財務の `complete=True` にかかわらず信用を取得する。価格・財務・空売り報告の再取得は行わない。
4. **取得窓**  
   更新開始時のJST日付Dを上端に、`code + from=D−89日 + to=D` の両端込み90暦日を取得する。価格基準日を上端にしない。20営業日、祝日、移行直後の週次点を収め、既存の約90日幅から大きく処理規模を変えないためである。90日あれば欠測が解消する保証は置かない。取得開始日を固定して再開し、取得窓をmanifestへ記録する。全ページ取得を完了条件とする。
5. **診断専用保存・再開**  
   `<cache>/margin_snapshots/<id>.json` と `latest_margin_snapshot.json` を設ける。既存 `latest_snapshot.json` を更新しない。元snapshot ID、対象銘柄、取得窓、診断締切、取得状態、原データ参照、アダプタ版を保存する。診断締切の既定値は当該収集の終了時刻とし、原データの取得時刻は別に保持する。予算・再試行・再開は信用専用に管理する。営業日カレンダーが不足する場合のみ、診断用に取得窓を含む期間を取得し、元snapshotのglobalsを変更しない。
6. **版管理・欠測管理**  
   行内容のハッシュと版ごとの初回観測時刻を保持する。完全一致行は計算用には重複排除し、原データは維持する。同一取得で同じコード・Dateに矛盾する行があり解決不能なら `conflicting_rows` とする。取得失敗時に過去成功値を現在値として復活させない。全ページ正常完了で0行なら新しい結果として `no_rows` とし、失敗と区別する。前回成功値は「前回観測」枠のみとする。
7. **オフライン診断出力**  
   `margin_analyze` を新設し、保存済み信用snapshotと参照価格snapshotから通信なしで計算する。`<output>/margin_history/<id>/` にmanifest、`margin_diagnostics.csv`、`margin_diagnostics.json`、`report_margin.md` を保存する。元順位は再計算・数値再掲せず、必要なら既存runへの参照を載せる。通常 `analyze_symbol` の信用診断も同じ定義を使用し、別締切の信用snapshotを暗黙に混ぜない。
8. **既存判定との分離**  
   信用の欠測・対象外・失敗・企業行動未確認を既存 `common_issues`、財務レビュー、ゲート理由へ流さない。信用診断専用の状態とする。採点関数、`legacy_reference_scores` の信用入力未接続、順位キーは維持する。

固定時刻に実行すれば必ず最新になるという契約は置かない。実行ごとの観測日・公表日・取得時刻を表示する。自動スケジューラの新設は第1段階に含めない。

`source_snapshot_id` だけでは同一snapshotからの任意の締切・設定による順位を一意に特定できない。将来順位を併記する場合は `source_run_id` と設定・結果ハッシュまで固定する。第1段階は診断専用出力として、この再採点・順位複写を行わない。

## 7. 受け入れ条件

以下は将来の実装後に確認する観点であり、テストコードや実行結果ではない。

1. **新旧契約の分離**：旧週次の追加項目欠落・nullを扱え、日次の必須項目欠落・契約不整合は理由付きで隔離される。
2. **検索条件**：独立信用更新は90暦日・全ページを対象とし、公表日検索と申込日検索を併用しない。価格日9月11日でも信用更新が9月11日で止まらない。
3. **完了銘柄の更新**：既存価格・財務の完了状態に妨げられず信用を取得でき、既存snapshot・価格日・最新snapshot参照を変更しない。
4. **欠測と実ゼロ**：行なし、対象外、権限不足、取得失敗、スキーマ未対応、未公表を別状態で出す。売残0・買残あり、両方0を有限倍率にしない。
5. **別データの混入防止**：空売り報告件数0・主体合計・SLRatioが信用売残や信用倍率へ混入しない。
6. **移行期間**：9月18日→25日を2営業日の橋渡しとして表示し、日次変化へ混ぜない。起点が異なれば実際の営業日差を記録する。
7. **最短日と履歴不足**：5営業日・20営業日変化は最短日以前に空欄となる。行の穴、基準値0、区分変更を補完して計算しない。
8. **企業行動と出来高**：企業行動や確認履歴不足で変化率を空欄にする。古い価格日の平均出来高を新しい信用残の分母へ流用しない。
9. **先読み防止**：公表前・取得確認前の締切では利用不可。日付だけの公表を当日朝から使用せず、訂正版を旧版の観測時刻へさかのぼらせない。
10. **古い価格との組合せ**：9月11日価格と9月25日以降の信用残は現在診断として識別され、9月11日当時の順位へ入らない。
11. **失敗と過去値**：取得失敗、正常0行、対象外への移行を以前の成功値で隠さない。前回観測は別表示になる。
12. **採点不変**：同じ元スクリーニング入力・設定なら、信用診断追加前後で推奨点、新規買い可否、レーン、旧総合点、順位が一致する。診断の失敗・欠測が既存レビューやゲートへ逆流しない。
13. **再現性**：保存済み診断snapshotから通信なしで同じ結果を得られ、原データ・版・締切・計算状態を追跡できる。
14. **表示**：空欄や投機性点0を「安全」と表示しない。元の価格日・元情報締切・診断締切・信用Date・PubDate・取得時刻を取り違えない。
15. **運用状態**：実データ監査未完了の成果物を検証済みと表示せず、本書に記載した最短公表日を実配信確認と混同しない。
