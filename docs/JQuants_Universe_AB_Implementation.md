## 対象と役割

- **A：割安・財務良好・成長**。6〜12か月を主軸、1〜3年を補助に検討する企業。安いだけの停滞企業を本命にしません。
- **B：高成長・信用売残**。高い評価水準も別基準で許容し、信用売残の積み上がりと日足の持続性を確認する候補。日計りを目的にしません。
- A・Bは独立したランキングです。各枠最大10件が既定、`--top`で件数を変更可能。両方に該当する銘柄は両方へ表示し、重複を明示します。点数を混合しません。
- ユーザーが候補を選び、外部売買Botへ手動登録します。資金配分・採用数もユーザーが管理します。約10%という運用意向から数量・配分・リバランスを計算しません。
- 上昇継続と条件待ちも対象にします。直近のMA200上抜けを新候補の必須条件にしません。順位変化は売却指示ではありません。
- 注文、売却、利確、外部BotのSTOP・ユニバース自動変更は実装していません。

## 通常の操作（1.3.0以降）

**起動 →「1：データを更新してスクリーニング」→ 完了を待つ → A・B候補を確認**。
初回、毎日の利用、数日空けた場合、中断からの再開も同じ操作です。日付・信用入力IDの選択は通常操作には不要です。

| 通常メニュー | 動作 |
|---|---|
| 1 | 取得・更新・時点確認・セクター再計算・A/B分析の一括実行。API通信あり |
| 2 | 保存済みA/Bレポートを表示。更新・採点しない |
| 3 | 保存済み単銘柄結果を表示。更新・採点しない |
| 4 | 最新の一括更新状況、データ基準日、対象・未評価・対象外件数を表示 |
| 5 | 旧メニュー1〜12の詳細操作へ移動。qで通常メニューへ戻る |

`python -B JQuamtsScreeningBot.py --phase screen` は通常1と同じ処理です。`runner.py` の既定も通常メニューになりました。単に起動しただけでは取得せず、「1」を選ぶと通信を開始します。

### 更新対象と履歴の再取得

- 対象銘柄一覧・カレンダー・TOPIXを取得し、その実行で利用可能な価格基準日を決めます。新規銘柄は必要な履歴を初期取得します。
- 実行ごとに価格、財務の新規開示・予想、決算予定を日付指定で更新します。価格・財務・決算予定の最古の確認日を使い、さらに直近7暦日を重複して確認します。株価より財務確認日だけが新しくても、途中の価格を飛ばしません。
- 財務と価格の全履歴取得日時を `last_full_financial_at` / `last_full_price_at` に分けて保存します。日付差分更新ではこれらを書き換えません。最終全履歴取得から30暦日以上、または履歴不足なら銘柄単位で再取得します。30日は本Botの運用方針です。
- 既存キャッシュには、生の銘柄指定レスポンスやその親参照から全履歴取得の根拠を探します。単なる差分更新日時を全履歴取得日時に流用しません。根拠がない場合は再取得対象です。
- 企業行動に伴う価格履歴の確認が必要な銘柄は、その銘柄の価格履歴を再確認します。通常の分割調整は既存の価格計算によります。
- 信用残は今回の対象銘柄について取得し、その取得IDを分析へ明示して固定します。信用取得後に価格・財務・決算予定を確認し、実際の取得証拠に基づく情報締切を確定します。日時だけを進めて取得済みにはしません。

Standardの財務配信目安は18時頃・翌0時30分頃、信用残は16時頃に前営業日の申込分です。前営業日の情報を確認する翌朝の実行を目安にできますが、配信時刻は保証ではありません。利用した価格日・信用申込日/公表日・取得時点を確認してください。[公式更新仕様（2026-09-30確認）](https://jpx-jquants.com/ja/spec/data-update)

### 対象外・未評価・失敗

一括実行では、マスタ上の一般投資家向け市場の普通株を対象にします。TOKYO PRO MARKET（`Mkt=0105`）は `screening_scope` の対象外として明示し、取得失敗数に含めません。保存済みの旧スナップショットや詳細操作の対象範囲は勝手に変更しません。

財務がHTTP 200の0行で返る場合は「財務データなし」です。同じ日に3回繰り返しても解消する前提にはせず、翌日以降に再確認します。通信・権限・形式の問題とは区別します。欠測銘柄を安全側に加点せず、新規上場の履歴不足を架空の値で埋めません。

通常スナップショットと信用入力を固定して時点を監査したうえで、個別不足があれば部分結果として公開します。全体の取得・鮮度確認が失敗した場合は、新しいランキングを公開せず前回結果を残します。分析中に価格の基準営業日が変わった場合も公開前に停止し、再実行を案内します。

## 共通の必須条件と保留

普通株の非金融企業を対象とし、現行の流動性・企業規模・比較可能な財務・黒字純利益・正の営業CF・営業利益安定・品質全7項目取得と5項目以上合格を要求します。既存の平均出来高5万株、平均売買代金3億円、時価総額500億円の初期値を変えていません。

データ不備・比較不能・確認保留は理由付き保留。確認された重大リスクや財務・流動性の不合格を高い成長点で救済しません。一過性利益の警告、利益品質の要確認、会計・ガバナンスのwatch、決算前blackoutも保留します。決算日未報告や外部ガバナンス未確認は個別確認事項として表示し、安全確認済みとは扱いません。

下降・過熱・価格状態不明はTopへ入れず保留します。底固めは品質6/7以上、21営業日騰落率が正、直近安値更新なし、risk_off以外を維持します。risk_offの上側候補には市場状態を注意表示します。条件待ちとデータ確認待ちを理由列で区別します。

## 成長とバリュエーションの初期値

次の3成長条件をすべて要求します。欠測は保留、既知の条件未達は当該枠から除外します。予想は有効な対象年度・開示時刻・正の純利益予想を確認し、前期実績比と同年度の予想修正を区別します。

| 条件 | A | B |
|---|---:|---:|
| 比較可能な4期からの3年売上CAGR | 3%以上 | 10%以上 |
| 実績営業利益前年比 | 5%以上 | 15%以上 |
| 有効な次期純利益予想の前期実績比 | 5%以上 | 15%以上 |
| PS | 0より大きく2以下 | 0より大きく10以下 |
| 保守的PER | 0より大きく60以下 | 0より大きく100以下 |

Bを赤字企業・財務不合格・流動性不足の救済先にしません。B条件を満たす割安企業はAとの重複を許容します。「高評価を許容」は「必ず割高であることを要求」ではありません。

## 需給・Bの追加条件

信用買残・売残は `/markets/margin-interest` の `LongVol` / `ShrtVol` を使用します。規制の空売り報告件数や主体別合算で置き換えません。信用だけでは売り手の意図、踏み上げの発生・時期を特定しません。

Bでは、日次の有効な信用残に加え、以下を要求します。

| 条件 | 初期値 |
|---|---|
| 売残株数 | 正 |
| 売残 / 直近20営業日平均出来高 | 1以上 |
| 売残の変化率 | 有効な20営業日変化が0%より大きい。20日が未計算なら有効5営業日変化を使う |
| 63営業日騰落率 | 0%より大きい |
| 63営業日のTOPIX相対リターン | 0%以上 |
| 売買代金の持続性 | 直近20日中央値 / その前60日中央値が1以上 |

20日減少を5日増加で救済せず、1日変化は使用しません。買残対出来高も売残と同じ検証済み分母で追加計算しました。出来高比は実際の決済必要日数の予測ではありません。5・20日変化は株数差分と変化率を併記し、比較不能・基準残高ゼロは数値へ置き換えません。

信用の日次開始直後は5・20営業日変化が不足するため、Bの確認待ち・候補なしは正常です。過去の週次残高を1営業日前の行として接続しません。

Aでは信用の欠測だけで財務・成長を否定せず「需給未評価」と表示します。信用の加点は行いません。以下は両枠で理由付きの注意表示とし、単独の倍率閾値による自動除外にしません。

- 買残/出来高が10以上、選択した20日または5日買残変化が10%以上、21日株価騰落率が−5%以下：買残増と価格の弱さを併記。
- 上記の買残増が30%以上：強い注意表示。
- 有効な売残増と21日株価騰落率−5%以下：売残増と価格の弱さを併記。
- 売残増と非負の21日騰落率：観測事実として表示。上昇予測・安全評価にしない。

## 時点・信用入力の契約

価格基準日と情報締切は通常snapshotから取得します。信用snapshotを指定しても通常分析の締切を延長しません。指定信用の全行を、通常分析の価格履歴・カレンダー・締切で再診断します。以前の信用レポートを単純joinしません。

- 指定なし：通常snapshotに保存された信用残のみ。
- `--margin-snapshot-id ID`：指定した信用snapshotのみ。失敗・未対象銘柄はその状態を残し、通常信用や過去の成功値へ戻しません。
- `--margin-snapshot-id latest`：明示指定時だけ最新の試行IDへ解決し、その具体的IDとhashをmanifestへ固定。
- 信用申込日が価格基準日を超える場合は複合評価へ使用しません。
- 公表日、初回観測と取得履歴、情報締切、銘柄コード、営業日系列、株数変更を検査します。
- 信用の申込日から情報締切まで3営業日超は需給未評価・B保留とします。
- 価格の鮮度は、凍結した情報締切時点で18時を過ぎた直近日足基準日までの営業日差で計算します。これは保守的な処理境界で、JPX公表時刻の主張ではありません。カレンダーの暦日網羅が不明なら鮮度も不明とし、3営業日超または不明ならA・Bとも保留します。
- 実行時の現在時刻では採点せず、同じ入力・締切・設定で再現できます。古い基準の結果は最新相場の判断とは表示しません。

9月11日の価格に9月末の信用残を組み合わせて、最新の登録候補を作ることはありません。1.2.0のA/B初期導入では価格更新を旧メニュー4へ分離していました。1.3.0の通常「1」は価格更新を内部で行い、価格・財務・信用の時点を確認してから候補を公開します。詳細操作の通常収集には従来の価格日固定を残しています。

## 点数の定義

各成分は0〜1の尺度に直して下表の重みを掛けます。必要な成分が欠けたら総合点は空で保留とし、残りへ再配点しません。別枠同士の点数の大小は比較しません。

| 成分 | A | B |
|---|---:|---:|
| 財務品質 | 35 | 25 |
| 成長 | 35 | 40 |
| 割安性／評価負担 | 25 | 10 |
| 価格局面／日足持続性 | 5 | 20 |
| 有効な信用売残の確認 | 0 | 5 |

`clip01(x)=max(0,min(1,x))` とします。

- 品質：`0.6×品質合格数/7 + 0.2×営業利益安定 + 0.2×営業CF正`。
- 成長：3指標それぞれの `clip01(実測値/(当該枠の下限×3))` の平均。
- A割安性：`0.4×clip01(1−PS/上限) + 0.3×clip01(1−業種比PS/2) + 0.3×clip01(1−PER/上限)`。
- B評価負担：PS・PERそれぞれの `clip01(1−値/上限)` の平均。
- A価格局面：上昇継続1、上昇転換0.9、底固め0.65。過熱0.2・下降0は診断点で、候補保留を解除しません。
- B持続性：`0.4×clip01(63日騰落率/0.30) + 0.3×clip01(TOPIX相対/0.15) + 0.3×clip01(売買代金持続性/2)`。
- B信用：`0.5×clip01(売残出来高比/3) + 0.5×clip01(選択した変化率%/50)`。

これらの尺度定数もRC初期設計です。候補条件を通過した各枠内で点数降順、同点はコード順とし、保留を件数補充に使いません。売残が多いだけで財務不合格を相殺することはありません。

## 設定

既存JSON設定の `REGISTRATION_RULES` 内で初期値を上書きします。未知のキー、不正な型・非有限値、重み合計100以外などは開始時に拒否します。全実効設定とhashをrun manifestへ保存します。銘柄の適合数に合わせて自動調整しません。

```json
{
  "REGISTRATION_RULES": {
    "A_MIN_SALES_CAGR": 0.03,
    "A_MIN_OP_GROWTH_PCT": 5.0,
    "A_MIN_FORWARD_GROWTH": 0.05,
    "B_MIN_SALES_CAGR": 0.10,
    "B_MIN_OP_GROWTH_PCT": 15.0,
    "B_MIN_FORWARD_GROWTH": 0.15,
    "B_MAX_PS": 10.0,
    "B_MAX_PER": 100.0,
    "MAX_PRICE_AGE_BD": 3,
    "MAX_MARGIN_AGE_BD": 3
  }
}
```

全項目は [UniverseConfig](../jq_universe.py) を参照してください。`OP_GROWTH_PCT`と信用変化は%表記、売上CAGR・予想成長・株価騰落率は比率表記です。重み設定を変更する場合は当該枠の全成分合計を100にします。
