# J-Quants Standard版 スクリーニングロジック正本

**仕様ID：`JQ-STD-CORRECTED-1.0-rc1`**  
**作成日：2026-09-11（日本時間）**  
**対象：`JQuamtsScreeningBot.py`／J-Quants API V2／Standardプラン・追加アドオンなし**  
**状態：修正後に実装する仕様。コード未適用・実データでの収益性未検証。**

> 目的は、**仕手株的な一時急騰ではなく、財務の裏づけがある割安株の上昇転換を捉え、その後の持続的上昇と残存上昇余地を評価すること**である。
> 本版では、既存戦略を土台に、誤計算・不整合・Standardプランに不適合な扱いを修正する。上昇余地と持続性の新指標は、まず診断・検証用として扱う。改善後の収益性は保証しない。

## 0. 本書の位置づけ・変更範囲

### 0.1 正本と実装の関係

現行動作の確認では、添付コードを旧マニュアルより優先する。本書は、その現行動作をそのまま説明する文書ではなく、**修正後の実装対象を定めた正本案**である。

- **現行実装**：出典 `[S1]` のコード。修正前の事実確認・比較に用いる。
- **修正後の仕様**：本書。実装後、適合テストと差分検証を通して運用基準にする。
- 不一致が残る間は「実装済み」としない。実装が本書と違う場合、差分を報告し、コードか本書のどちらを改訂したかを記録する。
- 本書の仕様番号は新設であり、リポジトリの既存バージョン番号・CHANGELOGを推定したものではない。

## 1. 実行対象・成果物

対象は、マスタで確認した国内普通株のうち必要な凍結データがある銘柄。全銘柄を同じ処理経路で分析する。初期版にテーマ別・銘柄別の手動加点は設けない。

最終的に区別するのは、次の四つである。

| 判定 | 主な列 | 意味 |
|---|---|---|
| バリュエーション候補 | `valuation_lane`, `core_candidate` | 流動性・規模・財務・バリュエーション条件を満たすか |
| 価格局面 | `ma200_state` | 再奪還、底固め、過熱、下降、未確認のどこか |
| 推奨レーン | `candidate_lane` | 新規検討候補か、監視か、要確認か、除外か |
| 定量的新規候補 | `eligible_new_entry` | 本書の定量条件をすべて満たしたか。発注許可ではない |

`core_candidate=True` だけを「今買うべき」と解釈しない。推奨点・グレードの高さでも、禁止条件を相殺しない。

## 2. Standardプランとデータ取得契約

### 2.1 利用範囲

2026-09-11に確認した公式仕様を基準とする。利用可能期間は、プラン上の上限と各データの提供開始日の両方で制限される。[R1]

| データ／エンドポイント | 本版の扱い |
|---|---|
| `/equities/master` | 必須。コード、商品区分、市場、33業種を取得 |
| `/equities/bars/daily` | 必須。日通しOHLC、出来高、売買代金、調整係数等 |
| `/fins/summary` | 必須。財務評価の正規データソース |
| `/indices/bars/daily/topix` | 市場レジーム用。収集して凍結する |
| `/markets/calendar` | 営業日・分析基準日の整合用 |
| `/fins/earnings-date` | 決算予定の公表履歴を収集。銘柄ごとの未定・未報告を許容 |
| `/markets/margin-interest` | 信用残の収集・診断。欠損をゼロ扱いしない |
| `/markets/short-sale-report` | 空売り報告の収集・診断。銘柄全体の総残高とは扱わない |
| `/equities/earnings-calendar` | 3・9月期企業向けの補助。上記決算予定APIの代用品にはしない |
| `/fins/details` | **無効**。Standardでは定常的な取得・403による探査を行わない |
| `/fins/dividend`、`/markets/breakdown`、前場専用データ | **無効**。必要な配当情報はsummary内の項目を利用 |
| J-QuantsのEDINET関連データ、TDnetアドオン | 本版の必須処理には追加しない。前者の一部はStandard対象でも、監査意見の検査とは別物 |

`financial_data_mode="summary_only"` はStandard版の**正常なモード**である。これだけを理由に全銘柄を `data_review_light` にしたり、グレードをBに制限したりしない。

ただし、「summary内で必要な値がない」「履歴が不足」「通貨・株数基準が不明」は別問題であり、要確認または採用不可とする。詳細が不要という意味ではなく、**本版の評価範囲がサマリーに限定される**という意味である。

### 2.2 認証・レート制限

認証は `x-api-key`。環境変数 `JQUANTS_API_KEY`／`JQ_API_KEY`、または `api.ini` の `[DEFAULT] API_KEY` を利用する。APIキーをログ・CSV・Gitへ保存しない。[S1:認証]

公式の基本上限はStandard全体120リクエスト／分、`fins/summary` は別途60リクエスト／分である。制限は変わりうるため、運用時も設定と429応答を尊重する。[R2]

本版の既定は既存の保守的な `JQ_RPM=60` を維持する。将来全体を増やしても、summary用の個別制限を越えない。ページング・再試行もリクエスト数に含め、同一プロセス内で送信前に枠を確保する。

- `JQ_DEFAULT_BUDGET=800` は引き続き**一回の収集バッチの銘柄数上限**。380などへの指定も可能。公式の日次上限ではない。
- `JQ_RPD` は任意の自主制限。未設定を「何をしても無制限」と表現しない。
- 401は認証異常として停止。必須APIの403は権限異常として停止し、企業の財務欠損に分類しない。
- 429・一時的な5xxは間隔を空けて再試行。再試行上限を設ける。
- 200の空配列は直ちに恒久除外しない。対象外、未開示、コード不一致、期間不足を区別して再確認する。
- ページング上限到達・途中失敗は `collection_incomplete`。部分取得を全件取得成功と表示しない。

### 2.3 初回収集と更新

初回は現行のcode単位取得を維持できる。ただし日々の再取得では、日付単位の価格・財務更新を利用して通信量を抑える経路を設ける。**Standardではsummaryの差分取得用 `cursor` を前提にしない。通常の `pagination_key` と混同しない。**[R3]

新API列 `MktCap`、`ExRT`、`ProdCat` 等は、公式仕様への掲載だけで既存キャッシュにもあると仮定しない。初回の生フィールド監査で、キー・値・単位・対象期間を確認する。[R4][R5]

## 3. 分析基準日・凍結キャッシュ・再現性

### 3.1 時点の定義

必ず以下を分けて保存する。

```text
price_asof_date       共通の価格基準日（取引所営業日）
information_cutoff    その分析で利用する情報の締切日時（JST）
collected_at          各データを実際に取得した日時
source_disclosed_at   開示日・開示時刻／公表日
run_id                分析実行ID
```

通常は、確定した日足と、収集時点までに利用可能な財務情報を使い、**分析後に来る取引機会**の候補を作る。引け後の決算を当日の終値で売買できたとする検証は禁止する。

Standardの財務更新は日次で、公式の目安は18:00頃の速報・24:30頃の確報。時刻は保証ではない。株価と財務の収集完了時刻が違うことを認識し、既存キャッシュの作成日時だけで鮮度を判断しない。[R6]

### 3.2 同一ランキング内の価格日を統一

同じランキングでは `price_asof_date` を統一する。銘柄ごとに「それぞれの最新日」を使って混在させない。当日の価格が取得できない銘柄は、原因を記録して当日の新規候補から外す。

数日に分けて初回収集した場合は、最終分析前に価格の共通日への更新と、各銘柄の財務収集鮮度の確認を行う。完全取得を確認できない時は `run_status="partial_universe"` と対象件数を明示する。全上場株の評価とは呼ばない。

### 3.3 真のオフライン分析

`analyze`・`single`・レポート生成では、J-Quants、EDINET、その他サイトへ**一切通信しない**。認証セッション作成も不要にする。

マスタ、TOPIX、決算予定、業種ベンチマークも凍結データだけを使う。不足時にネット取得や代表5銘柄への置換を行わず、不足を返す。必要なグローバルデータがない場合は新規候補の正式出力を停止し、診断レポートのみ生成する。

### 3.4 Point-in-timeの限界

開示締切後の訂正を過去の判定に混ぜない。ただし、API側の訂正による上書き等があるため、**いま取得した過去データだけで、当時の取得内容が完全に再現できるとは限らない**。[R6]

保存開始後は生レスポンスとその取得日時を固定保存する。過去検証では `pit_quality` を記録し、当時のデータ版がない検証と、実運用スナップショットの前方検証を分ける。

## 4. 銘柄コード・商品分類・セクター

### 4.1 コードの正規化【修正】

コードは常に文字列。数字だけの抽出、浮動小数への変換、任意の先頭4文字切り出しを禁止する。

- 内部キーはマスタで確認した4文字の普通株コード。英文字を保持し大文字に統一する。
- API用の5文字コードもマスタから保持する。4文字入力からの末尾0付加は、普通株のマスタ対応を確認してから行う。
- 例：`130A` と `130A0` は同じ普通株に対応するが、`0130`・`1300` へ変換してはならない。
- 異常な桁数、余計な文字、曖昧なコードは `invalid_code`。曖昧な旧キャッシュ名を別銘柄へ救済しない。
- CSV読込は `code`、`Code`、`S33`、`Mkt`、`ProdCat`、`DiscNo` を文字列指定する。

### 4.2 商品分類【修正】

`ProdCat`、マスタ上の普通株対応、市場情報を優先する。`ProdCat=011` は内国株券であり、それだけで優先株等まで普通株と断定しない。商品区分が使えない場合のみ、既存の市場・商品名フィルタを補助に使う。[R5]

ETF・ETN・REIT・投信・優先出資・外国株等は普通株の財務順位へ混ぜない。「金」「原油」等の一般語やコード帯だけで、マスタが確認した普通株を落とさない。分類不能は `instrument_type="unknown"` として別出力する。

### 4.3 セクター正規化【修正】

相対評価の主キーは **公式33業種コード `S33`** とする。業種名は表示用に保持する。鉄鋼、鉱業、非鉄金属、石油・石炭製品等を「その他」へ落とさない。`その他製品` と業種不明の `その他` も区別する。[R5][R7]

「半導体」「商社」「ゲーム」等の独自ラベルは補助属性に留め、銘柄ごとに恣意的な比較母集団を変えない。欠損補完用の辞書を、公式業種の有効性判定に使わない。

### 4.4 金融業の適用範囲【初期運用方針】

銀行・証券・保険・その他金融業（S33：7050／7100／7150／7200）は、一般事業会社用のPS・営業CF・負債比率評価をそのまま自動採用判定へ使わない。収集と参考出力は行い、`model_scope_review` に分離する。

これはデータ欠損でも「悪い企業」判定でもなく、**モデルの適用範囲による保留**である。本版で新たに置く保守的な運用方針であり、純粋なバグ修正とは区別する。金融向けモデルの新設は別仕様とする。

## 5. 株価・調整係数・時価総額

### 5.1 価格の用途を分ける【修正】

| 用途 | データ |
|---|---|
| 実際の株価表示・注文価格の参照 | 調整前の当日終値 `C` |
| MA・RSI・ADX・モメンタム・最大DD・ボラ | 同一基準へ調整したOHLC |
| 売買代金 | `Va` を優先。単位は円 |
| 出来高の時系列比較 | 分割・併合を調整した出来高 |
| 当日の時価総額 | `MktCap` が有効なら優先。**百万円から円へ変換** |

日足には `MktCap` と権利落ち種別 `ExRT` が定義される。`ExRT=1/2/3` は分割／併合／ライツイシュー。時価総額は上場株式数ベースであり、自己株式控除後と勝手に読み替えない。[R4]

### 5.2 調整の契約

価格日 `t` から共通基準日 `T` までの価格累積係数を、`t` より後、`T` 以前の対象イベントの `AdjFactor` の積とする。

```text
price_adjusted_to_T[t] = price_raw[t] × price_factor(t, T)
```

分割・併合による株数・出来高調整では、そのイベントだけの係数を別に管理する。**ライツイシューの価格調整係数を、株数の単純な逆数換算へ流用しない。** 公式もライツイシューの出来高は調整しないとしている。[R4][R8]

APIの `AdjO/H/L/C/Vo` を使う場合も、基準日と調整方式を記録する。過去日分析では基準日後のイベントを排除し、調整前価格とイベント履歴から基準日へ再構築する。OHLCの一部だけを調整したり、調整済み終値と未調整高安を混ぜたりしない。

`AdjFactor!=1` なのに権利落ち種別を確認できない場合、その係数を株数・出来高調整へ推定流用しない。価格の調整は確認済みのAPI定義に従って計算できても、株数比較は `corporate_action_basis_unknown` として保留する。イベントがない日の正常なExRT=nullと、古いキャッシュにExRT列自体がない状態は区別する。

株価系列の欠損を終値で埋めて取引があったように見せない。取引日が抜ける場合は不足として扱う。指標の必要本数を満たさない場合は `None`。

### 5.3 時価総額とフォールバック

優先順位は次のとおり。

1. 有効な当日 `MktCap × 1,000,000`：`market_cap_source="jquants_daily"`。
2. それがなければ、最新の利用可能開示の期末発行済株式数を、**基準が確認できる分割・併合だけ**調整し、当日株価を掛けた代理値。`market_cap_source="disclosed_shares_proxy"`。
3. 株数基準・資本異動が解決しなければ `None`。

第2経路は開示後の増資・消却等を完全追跡した時価総額ではない。`shares_asof_date`・経過日・代理値である旨を表示し、`light` の確認事項とする。過去年度の株数を無条件に「現在株数」と呼ばない。

### 5.4 流動性

```text
avg_volume_30d = 直近30営業日の分割・併合調整済み出来高の平均
adv_jpy_20d    = 直近20営業日の Va の平均
adv_jpy_60d    = 直近60営業日の Va の平均
```

主判定は `Va` を使う。欠損時の `C×Vo` は診断用の近似として別列へ保存し、実際の売買代金と黙って混ぜない。必要期間の有効データが揃わなければ流動性判定は `unknown`。

出来高閾値は株数単位なので、実際の分割で通過状況が変わりうる。金額ベースの流動性と分割情報も併記し、「すべての条件が分割に不変」とは要求しない。

## 6. 財務サマリーの正規化・比較基準

### 6.1 必要な項目と意味

生レスポンスを保持し、最低限以下を正規化する。未収録項目は `None` と理由を残す。[R3]

| グループ | 主な生キー | 注意 |
|---|---|---|
| 開示・期間 | `Code`, `DiscNo`, `DiscDate`, `DiscTime`, `DocType`, `CurPerType`, `CurPerSt/En`, `CurFYSt/En`, `NxtFYSt/En` | 開示日と対象期間を混同しない |
| 損益 | `Sales`, `OP`, `OdP`, `NP` | IFRS等の経常利益欠損は制度上の非該当の場合がある |
| 資産・資本 | `TA`, `Eq`, `ShEq`, `EqAR`, `BPS`, `ROE` | `Eq` は純資産、`ShEq` は自己資本。別々に保存 |
| CF・現金 | `CFO`, `CFI`, `CFF`, `CashEq` | 現金を流動資産で代用しない |
| 一株指標・株数 | `EPS`, `DEPS`, `ShOutFY`, `TrShFY`, `AvgSh` | 期末発行済・自己株・期中平均は別物 |
| 配当 | `DivAnn`, `DivTotalAnn`, `PayoutRatioAnn`, `FDivAnn`, `NxFDivAnn` 等 | 年間合計と期末配当を区別 |
| 予想 | `FSales`, `FOP`, `FNP`, `FEPS`, `NxFSales`, `NxFOP`, `NxFNp`, `NxFEPS` | 通期予想と2Q予想を混ぜない |
| 比較可能性 | `RetroRst`, `ChgByASRev`, `ChgNoASRev`, `ChgAcEst`, `SigChgInC` 等 | 変更があることと不正・重大欠陥は同義ではない |

`DivFY` を `DivAnn` の無条件フォールバックにしない。`NxFNp` の大文字小文字差を明示的に対応する。連結値がないからといって一部の項目だけ非連結値を混ぜない。

`equity_ratio` は `EqAR`、または意味が確認できる `ShEq/TA` を使う。`Eq/TA` は `net_assets_ratio` として別表示する。`TA-Eq` は負債相当の合計であって、有利子負債・ネットデットではない。

会計通貨が株価・時価総額の円と一致しない場合、確認済みの換算処理なしにPS/PERを算出しない。通貨の項目が提供されないケースは、監査で確認した例外設定を版管理し、不明を無条件に円とみなさない。

### 6.2 年次履歴の選択【修正】

まず情報締切以前に利用可能な行へ絞る。次に、銘柄・連結区分・会計期間開始終了・期間種類ごとに、利用可能な最新開示を選ぶ。**最後に決算期末の新しい順へ並べる。**

`current` は最新の通期実績、`previous` はその直前の比較可能な通期実績。過去期の訂正が後日出ても、その古い決算期をcurrentへ昇格させない。

訂正が部分項目だけの場合、同一対象期・同一会計範囲と確認した項目のみ更新し、項目ごとの出典開示番号を残す。「空欄＝撤回」か「空欄＝変更なし」か判定できない予想訂正は、都合よく古い数値を復活させない。

年次判定は `CurPerType=FY` と期間情報を主に用い、日付文字列や書類名の一部だけで判定しない。連結／非連結の変更、決算期変更、変則決算は比較可能性を検査する。

通常通期は開始・終了日から12か月の会計期間であることを確認し、月末・うるう日の差はカレンダーに従う。隣接年度の連続性も確認する。「FYという文字がある」「期末年が一つ違う」だけでは通期比較可能としない。期間が確定できなければ `annual_comparability=unknown` とする。

### 6.3 営業利益安定・売上CAGR【維持＋修正】

営業利益安定は、**比較可能な連続3期の通期実績**を要求する。

```text
OP0 > 0, OP1 > 0, OP2 > 0
かつ OP0 >= 0.60 × median(OP1, OP2)
```

1期・2期しかなければ `stable=None, reason="insufficient_annual_history"`。赤字・ゼロは `False`。欠損は `None`。`years_checked` は実際の比較期数を返す。

3年売上CAGRは4期分を必要とし、正の売上値と約3年の期間対応を確認する。非年次・欠けた年度の飛び越し・短期決算の単純年率換算はしない。

```text
sales_cagr_3y = (Sales0 / Sales3)^(1/3) - 1
```

最新通期実績が古い場合は、開示経過日と決算期末からの経過日を両方表示する。過去期の訂正だけで業績情報が新しくなったと判定しない。通常約1年で更新される年次実績を、200日経過だけで自動的に劣化扱いしない。

### 6.4 EPS成長と保守的PERを分離【修正】

次の数値を混ぜない。

| 列 | 定義 |
|---|---|
| `eps_reported` | APIの報告EPS。株数基準を検証できた場合に限り比較・価格除算へ使う |
| `eps_proxy_endshares_yoy_pct` | 各期NPを各期の発行済株数（同じ分割基準へ換算）で割った代理EPSの前年比。**報告EPSではない** |
| `np_yoy_pct` | 直近通期NPと前期通期NPの増減率。前期が正の場合のみ |
| `forward_np_change` | 対象期間を確認した会社予想NP／直近通期実績NP−1。比率単位 |
| `forecast_revision_rate` | 同じ対象期の前回会社予想からの修正率。初期は診断専用 |

初期版のFEで従来EPS成長枠に渡すのは、混合期間を解消した `eps_proxy_endshares_yoy_pct`。既存の期末株数方式を修正・明示して比較可能性を保つ。将来、報告EPS／期中平均株数方式へ変更する場合は別の検証を行う。

一株指標の調整済み基準が不明な場合は計算しない。株数増減だけから分割を推定しない。過去EPSが既に遡及修正されている場合は二重調整しない。大きな第三者割当や消却を「分割」として打ち消すことを禁止する。

### 6.5 バリュエーション

本版の主PS/PERは時価総額ベースに統一する。

```text
PS                   = market_cap_jpy / 最新通期Sales
per_actual           = market_cap_jpy / 最新通期NP
per_forward          = market_cap_jpy / 対象確認済み予想NP
per_conservative     = market_cap_jpy / min(最新通期NP, 予想NP)
```

予想NPが利用できない場合、保守的PERは実績側のみで算出し、`forward_missing` を表示する。分母がゼロ以下なら対応するPERは `None` とし、負のPERで割安判定しない。

これらは上場株式時価総額基準であり、報告EPSの期中平均株数・自己株式控除基準とは異なる場合がある。互換列 `per` は `per_conservative` の別名とし、`per_basis="market_cap_over_np"` を必ず出す。報告EPS基準のPERを併記する場合は別列にする。

予想EPSしかない場合は、株数基準が検証できるときだけ独立の予想PERを計算する。これを未検証の予想NPへ逆算して、主PERへ黙って代入しない。

### 6.6 会社予想の選択【修正】

最新通期実績を基準に、進行中または翌期の対象FYを選ぶ。同じ対象期について、利用可能な最新開示を採用する。

- FYの翌期予想は `Next/NxF*`、対象期は `NxtFYSt/En` を優先する。
- 四半期・業績予想修正は `F*` の通期予想を使い、対象期は `CurFYSt/En` 等で検証する。
- 既に通期実績が出た対象期の旧予想は使わない。
- 明示的に不正な期間として棄却した予想を、下流の `_non_null` 等で復活させない。
- FY+12か月を対象期確定の根拠にしない。補助推定は表示できるが、正式採用には期間確認が必要。
- 予想の取り下げ・未定を検出した場合は、同一期の古い予想へ自動的に戻さない。意味が解釈できなければ `guidance_status="ambiguous"`。

成長率の正式採用には比較可能な通常の通期を要求する。変則決算は `forward_period_irregular` として別扱い。前期赤字からの回復を正の通常増益率に変換しない。

## 7. Standard版の財務品質評価

### 7.1 名称と評価項目【Standard対応】

名称は **`summary_quality_7`（サマリー財務品質7項目）** とする。現行コードの独自Piotroski系評価のうち、summaryで評価する7項目を明示したもので、原著のPiotroski F-scoreそのものではない。[S1:calculate_piotroski_real]

| 番号 | 条件 | 現行からの扱い |
|---|---|---|
| Q1 | 最新通期 `NP > 0` | 維持 |
| Q2 | 最新通期 `CFO > 0` | 維持 |
| Q3 | 最新通期 `CFO > NP` | 維持 |
| Q4 | `NP / 期末TA` が前年より改善 | 現行の期末TA方式を維持。別のROA定義と混ぜない |
| Q5 | `CFO / Sales` が前年より改善 | 維持 |
| Q6 | 分割・併合基準を揃えた発行済株式数が前年より減少 | 維持＋分割誤認修正。増資なし判定や自社株買い実績そのものではない |
| Q7 | `(TA - Eq) / TA` が前年より低下 | 維持。ただし総負債比率の代理評価と明示 |

流動比率改善・売上総利益率改善は対象外。これらを推定値で埋めたり、偽の合格にしたりしない。Q6を「株数が増えていなければ合格」に緩和する変更や、Q5を資産回転率へ変える変更は本版では実施しない。

### 7.2 欠損と点数

```text
k = 合格した項目数
n = 計算できた項目数
summary_quality_score     = k
summary_quality_available = n
summary_quality_coverage  = n / 7
quality_normalized_9      = 9 × k / n  （n > 0 の場合のみ）
```

`quality_normalized_9` は旧FEとの接続用の尺度変換であり、未取得の2項目を観測したことにはならない。表示は「5/7、取得7/7」のようにする。「Piotroski 6.43/9を実測」と表示しない。

**新規候補の財務品質条件**：

| 経路 | 必須条件 |
|---|---|
| `ma200_reclaim_core` | n=7、k≥5、Q1=True、Q2=True、営業利益安定=True |
| `bottom_reversal_core` | n=7、k≥6、Q1=True、Q2=True、営業利益安定=True |

k≥5／6は、7項目観測時における旧調整スコア6.0／6.5の境界を参考にした初期設定。Q2の明示必須化は、持続的上昇の裏づけを求める**初期運用方針**であり、単なる等価変換ではない。

n<7は取得・比較不能の理由を付けて `data_review`。n=7で低得点は `financial_quality_watch`。**データ品質と企業品質を同じ理由コードにしない。**

## 8. 財務健全性・株主還元・会計情報

### 8.1 利益品質

既存の次の指標を保持するが、値が計算できた場合だけ評価する。

```text
accrual_ratio = (NP - CFO) / TA
np_to_ordinary = NP / OdP
op_margin = OP / Sales
```

現行の警告閾値（accrual>0.12、NP/OdPが0.45未満または0.90超、営業利益率の過去比スパイク）は、最適値とせず初期診断に維持する。指標ごとの計算可否を記録する。[S1:compute_earnings_quality_metrics]

- IFRS等でOdPが非該当ならその項目を除外し、欠損ペナルティにしない。
- 営業利益率が過去平均との差で上がっただけでは、一過性利益と断定しない。
- 過去の営業利益率に一律0.70を掛けた `normalized_eps`／`normalized_per` は**税率・営業外損益を仮置きした診断用代理値**。目標株価や確定的な割高判定へ使わない。
- 利益品質が `watch` かどうかは、適用可能な指標のうち実際に閾値を超えたものに基づく。全部計算不能なのに `ok` と返さない。

初期の順位調整に使う `earnings_quality_watch` は、accrualまたは適用可能なNP/OdPの異常で立てる。利益率スパイクと固定0.70係数によるgapだけの警告は診断用に留める。これは**代理仮定だけで実質減点していた扱いの見直し**である。

### 8.2 株主還元Q【修正】

過去実績の評価と会社予想の評価を分ける。実績系列の穴を将来配当予想で埋めない。年間合計DPSを使い、分割基準が不明ならDPS増減の評価を止める。

配当総額は同じ通期の `DivTotalAnn` を優先。DPS×株数で代用する場合は配当の対象株数・分割基準を確認し、`dividend_total_proxy` と明示する。

配当支払余力成分は次のとおり。

```text
CFO > 0 かつ配当総額が既知：
  capacity = max(0, 1 - min(1, dividend_total / CFO))
CFO <= 0 かつCFOが既知：
  capacity = 0
必要データが未知：
  capacity = None
```

**CFOの赤字化や欠損化によって、capacityの評価を上げてはならない。** 配当総額／CFOは同一期の開示額を用いる代理評価であり、実際の現金支払タイミングまで一致すると断定しない。

株主還元Qの基本配分は、現行を引き継ぐ。

| 成分 | 最大点 | 修正後の条件 |
|---|---:|---|
| 支払余力 | 35 | 上記capacity×35 |
| 配当継続性 | 30 | 比較可能な年間実績DPSが3期以上。現行の増減配判定を使用 |
| 発行済株数減少の継続性 | 20 | 分割を除いた株数系列で計算。自社株買い実績とは呼ばない |
| 実績配当の存在 | 15 | 年間実績DPS>0。DPS=0は0点、欠損は未知 |

配当継続性は、連続する比較可能年度で、減配 `cur < prev×0.95`、増配 `cur > prev×1.02` とし、`clip(0.45+0.12×増配回数−0.25×減配回数, 0, 1)` を用いる。全期無配なら0。過去窓は利用可能な直近最大5期に固定する。

株数減少の継続性は、比較可能な3期以上の系列で、最新と最大3年前とのCAGRが−1%未満なら1、負なら0.5、それ以外0。年数は実際の期間に合わせ、欠けた期を詰めて計算しない。

配当性向は、同一通期の配当総額／NP（NP>0の場合）で計算する。既存の減点を次のとおり明示する。

```text
payout_penalty = min(0.35, max(0, payout_ratio - 0.80) × 0.60)
balance_strain = 1  if 自己資本比率が前年比3ポイント超低下
                       AND 現金・現金同等物が減少
                       AND payout_ratio > 0.60
                 0  if 必要値が確認でき、上記の併存なし
                 None if 判定に必要な値が不明

shareholder_return_score = clip(
  35×capacity + 30×dividend_credibility + 20×share_decrease_consistency
  + dividend_presence_points - 20×balance_strain - 100×payout_penalty,
  0, 100)
```

`balance_strain` は財務余力の悪化を示す代理条件であり、「借入で配当した」と確認できた意味ではない。

必要な成分・減点判定が不足する場合、`shareholder_return_score=None` とし、計算済み成分の点数と `shareholder_return_coverage` を別に出す。成分の不足を満点や再配点で隠さない。配当総額が正なのにNP<=0の場合は `payout_ratio=None, payout_status=loss_making_payout` とし、還元Qによる加点を認めない。

株主還元Q≥70による順位+3は、全成分と適用する減点条件を評価できた銘柄に限定する。未確認の還元Qでデータレビューの圧縮基準を緩めない。

### 8.3 会計・ガバナンス

`ChgByASRev=True` 等は、会計方針や見積り等の変更を示す。自動的に「不正」「監査重大問題」「財務危険」と読み替えない。[R3]

`comparability_flags` と、証拠に基づく `accounting_risk`／`governance_risk` を分ける。真偽値文字列は明示的に解析する。`"False"` を `bool()` でTrueにしてはならない。

本版では、従来のEDINET書類名の14日おき走査を無効にする。外部確認がなければ `governance_status="not_checked"`。一般的な「内部統制」「監査報告」という書類名だけでwatchを立てない。「問題が見つからない」と「調べていない」を区別する。

別途確認済みの重大問題がある場合は、根拠・確認日時・有効期限を付したローカルの `risk_overrides` に保存し、レーンより優先する。単なる会計方針変更を、この重大問題リストへ自動投入しない。

## 9. セクターベンチマークと採点母集団

### 9.1 二段階計算【修正】

**第1段階**：全対象銘柄の正規化済み価格・財務・PS/PER等を計算する。  
**第2段階**：同一基準日の母集団から業種統計を一度だけ計算し、その固定値を使って全銘柄を採点する。

業種PS基準は、当日分析対象のうち、コード・商品・業種・通貨・時価総額・年次売上の基準が有効な普通株のPS中央値。Coreだけに絞る前の母集団を使う。赤字でもPS入力自体が有効なら、PS母集団から恣意的に除かない。

業種ごとに**有効PSが5銘柄以上**ある場合のみ使用する。5は既存のpercentile処理を踏まえた最低限の初期設定で、統計的な十分性を保証しない。`sector_sample_count` と対象数の偏りを表示する。

有効数不足、S33不明、データ異常は `sector_benchmark=None`。手入力の「その他PS=1.5」等で割安さを偽造しない。参照値欠損は `light` の確認事項とする。

### 9.2 出力不変性

`ps_vs_sector = PS / sector_ps_median` を一度だけ計算する。percentileも同じ固定母集団で一度だけ算出する。銘柄数は当該指標の非欠損数で数える。

**全銘柄CSV、Core一覧、単銘柄、Top10、Markdownで再採点しない。** 出力関数は絞り込み・並べ替え・表示だけを行う。単銘柄分析は同じ `run_id` の業種統計を読む。統計がなければ単独相対順位を作らない。

## 10. テクニカル・市場レジーム

### 10.1 計算定義【修正・一部維持】

日足の窓は、単なる観測行数ではなく取引カレンダーと対応する営業日。窓内の必要な価格が欠ければ計算不能とする。最新価格でMAを代用するなどの処理を禁止する。

| 指標 | 定義 |
|---|---|
| MA25/75/200 | 調整終値の単純移動平均。必要本数未満はNone |
| 21/63/126/252日リターン | `P_T / P_(T-n) - 1` |
| MA25の20日変化 | `MA25_T / MA25_(T-20) - 1` |
| RSI14 | 既存の単純平均方式を維持。Wilder式とは呼ばない |
| ADX・DI14 | 既存のEMA方式（alpha=2/15）を明記して維持。Wilder式への変更は別検証 |
| ボラティリティ | 日次単純リターンの標本標準偏差（ddof=1）。20日と基準窓を別列にする |
| 年率ボラ | `vol_daily × sqrt(252)`。一度だけ年率化 |
| 最大DD | 基準日から過去700暦日内の価格について計算。初期の既存価格取得窓を明確化 |

RSIは、平均上昇>0・平均下落=0なら100、逆なら0、両方0なら50。履歴不足はNone。ADX・DIは値を5に底上げせず、計算可能なゼロは0。欠損を20などで代用しない。

ADX・DIは既存と同じTR、+DM、−DMを作り、`ewm(alpha=2/15, adjust=False)` で平滑化する。十分な観測済みOHLCにおいて、平滑TR=0かつ両DM=0なら両DI=0、両DI合計=0ならDX=0と定義する。正しい横ばい実測系列と、価格欠損を区別する。必要OHLCが不足する場合はNone。ADX・DIの値域は0〜100で、旧5〜80／5〜95への切り詰めは採点へ持ち込まない。

ボラの基準窓は過去700暦日内の利用可能な連続日次リターンとする。日付の欠けた区間を飛び越した複数日変化を、1日リターンへ混ぜない。

ボラの列名は `vol_daily_20d`、`vol_annual_20d`、`vol_daily_reference`、`vol_annual_reference` とする。旧 `volatility` を残す場合は年率列の別名と明示する。flattenで欠落させない。固定0.022で実測のように補完しない。

### 10.2 市場レジーム【Standard対応】

正規データは凍結したTOPIX。代表8銘柄の単純平均をTOPIXと呼ばない。旧プロキシは比較診断にのみ残す。

TOPIX終値、MA200、MA25の20営業日変化率を使い、コードの実際の閾値を維持する。[S1:evaluate_market_regime]

```text
risk_on : P > MA200, d200 >= +0.02, slope25 >= -0.005
risk_off: P < MA200 かつ (d200 <= -0.03 または slope25 < -0.01)
neutral : 上記以外（必要値がすべて観測済み）
unknown : 必要な指数データ・計算値が不足
```

`unknown` を `neutral` に置き換えない。正式な新規候補判定には既知のレジームを必要とする。risk_offではreclaimのFE下限を70から75へ上げ、bottomの新規採用を止める。

## 11. MA200の価格局面

### 11.1 基本定義

```text
d200 = 調整終値 / MA200 - 1
cross_up = 前営業日P < 前営業日MA200 かつ 当日P >= 当日MA200
recent_cross = 直近20営業日にcross_upが存在
```

直近20営業日分のクロス有無を判定するには、当日を含め220営業日の連続した必要価格を要求する。MA200だけが計算できてもクロス比較窓が欠ければ、本版の新規候補判定は `ma200_unknown` とする。252日リターン等の長い診断窓の不足は、当該診断列だけNoneにする。境界 `P=MA200` は、クロス検出と整合するよう上側に含める。価格の整数丸めや表示用の丸めで分岐させない。

### 11.2 上側の分岐順【修正】

**過熱を直近クロスより先に判定する。**

| 条件 | `ma200_state` |
|---|---|
| d200>0.15 | `above_ma200_extended` |
| 0≤d200≤0.15、recent_cross=True | `ma200_reclaim` |
| 0≤d200≤0.15、recent_cross=False | `above_ma200_near` |

直近クロスの事実は `crossed_above_ma200_recently` として残す。d200>15%でも「最近上抜けたから本命」という上書きは禁止する。0〜8%を理想帯とする従来の点数補正は維持する。

### 11.3 200日線下の下降拒否【維持】

P<MA200のとき、次のいずれかに該当すれば下降拒否。

```text
P < MA25 かつ slope25 < 0
直近10営業日に60営業日安値を更新
21営業日リターン < 0
minusDI / plusDI > 1.3 かつ ADX >= 20
d200 < -0.25
```

60日安値更新は、その営業日の終値が**直前60営業日の終値最小値以下**かどうかで調べる。plusDI=0かつminusDI>0は下向き優勢、両方0は方向なしと明示し、ゼロ除算で良好扱いしない。

### 11.4 底固め【維持】

P<MA200かつ下降拒否なしで、以下をすべて満たす。

```text
1. d200 >= -0.25
2. P > MA25 または slope25 > 0
3. 21営業日リターン > 0
4. 直近10営業日で60日安値更新なし
5. 120営業日の終値最安値から8%以上反発
6. ADX <= 35 または 5営業日前よりADX低下
7. minusDI / plusDI <= 1.2（方向なしの場合は条件を満たす）
8. 直近60営業日の終値最小値 > 直近120営業日の終値最小値 × 1.0001
```

データ欠損でDIの条件を省略して通さない。計算不能と、両DI=0で方向なしという実測状態を分ける。

この8番目は、「120日最安値が直近60日より前にある」ことを実質的に求める厳しい条件である。**本版では緩めない。** 直近数週間の急反発より、長い底固めを優先する既存経路として維持する。

条件成立は `below_ma200_basing`。不成立は `below_ma200_downtrend` として新規不採用を維持するが、明確な下降と単なる底固め未確認を `ma200_reason` で区別する。

`above_ma200_near` は、今回の「転換直後」の新規候補にしない。監視分類を明示し、分岐の抜けで誤って不適格企業と同じ表示にしない。

## 12. 決算予定・会社予想悪化・リスク制約

### 12.1 決算予定【修正】

`/fins/earnings-date` の公表履歴から、情報締切時点で有効な予定を復元する。変更前の予定を使い続けず、未定に変更された場合は未知へ戻す。[R9]

`FYE` は月日であるため、決算年度を持つ通期末日と混同しない。銘柄・決算区分・報告履歴を確認し、同じ1Qでも別年度の予定を混ぜない。

予定日が既知で、**想定する次の売買日から発表日まで0〜2営業日**なら `earnings_blackout=True`。暦日+92日という推定は本判定に使わない。2営業日は本書で単位を統一した初期運用方針である。

予定の情報がない場合は `earnings_status="unknown"` と `pretrade_check_required=True`。不明を「決算が近くない」と断定しない。一方、APIが正常に取得できたうえで当該企業の予定が未報告というだけで、財務スコアそのものを落とさない。

blackoutは新規候補から除くが、保有株の自動売却指示にはしない。

### 12.2 会社予想の悪化【維持＋修正】

対象期が有効で `forward_np_change <= -0.30` の場合は `forward_downgrade_watch`。予想NPがゼロ以下もこの制限に含む。実績NPが正でなければ通常の増減率を作らず、別の収益不適格理由とする。

過去実績からの減益と、同一対象期の下方修正は別列。予想NPがないのに、予想EPSの基準不明値で減益率を作らない。

### 12.3 重大リスク

確認済みの重大会計・監査・ガバナンス問題は `risk_blocked`。単なる小さな減点としてレーン順位より後へ回さない。

信用倍率やボラが大きいだけで、重大不正や仕手株と断定しない。Standardでは監査本文・全ての適時開示を自動網羅する仕様ではない。定量候補は、最終的な個別確認を省く根拠にはならない。

## 13. スコアの正本

### 13.1 三本柱と順位点

| 名称 | 列 | 意味 |
|---|---|---|
| ファンダメンタル・エッジ | `fundamental_edge_score` | 割安性と財務品質を中心とする0〜100点 |
| エントリー複合点 | `entry_score` | FEに価格局面補正を加え、レーン別圧縮をした点数。純粋なタイミング点ではない |
| 旧総合参考点 | `legacy_total`（互換：`total_score`） | 旧方式の比較・診断用。新規採用の必須条件ではない |
| 推奨順位点 | `recommendation_score` | 原則として同じレーン内で使う点数。期待リターンではない |

本版では重みの最適化を同時に行わない。旧 `entry_timing_score` 表記は「エントリー複合点」へ変更する。純粋な価格局面を示す `ma200_timing_score` は診断列であり、entryと混同しない。

### 13.2 FEの加点

配分は既存を基本維持し、入力基準とStandardの扱いを修正する。

| 要素 | 条件と点数 |
|---|---|
| PS | 0<PS≤0.35：18、≤0.70：15、≤1.20：11、≤2.00：7、2.00超：3、未知／無効：0 |
| 業種比PS | 比≤0.55：22、≤0.80：18、≤1.00：14、≤1.10：9、1.10超：3、未知：0 |
| PEG品質 | trustedかつok：14、trustedかつexpensive_or_moderate：8、caution：5、その他／未知：0 |
| サマリー品質 | `22 × k/n`（n>0）。n<7では点数は参考値で、新規採用不可 |
| 営業利益安定 | True：9、False／None：0 |
| 売上CAGR | ≥15%：6、≥8%：4、≥0%：2.5、その他／未知：0 |
| 代理EPS成長 | 5〜45%：5、45%超〜80%：2、その他／未知：0 |

Standardで取得対象外の2項目を理由とした旧Piotroskiの多重カバレッジ減点を外す。未知のPEGへ1点、未判定の営業利益安定へ2点を加える処理はやめる。これにより旧FEと完全一致しないため、同じ70／75点でも旧版の母集団と同等と断定しない。

### 13.3 PEG品質

`reference_peg = per_conservative / eps_proxy_endshares_yoy_pct`。成長率は「10%なら10」を入れる。成長率≤0、PER無効、株数基準不明はNone。

| 条件 | 評価 |
|---|---|
| PEG<0.10 | `extremely_low_possible_oneoff` |
| 0.10≤PEG<0.30 | `very_low_check_cyclical`、caution |
| 代理EPS成長>80% | `eps_growth_too_high_oneoff_risk` |
| 0.30≤PEG≤1.20、上記警告なし | trusted、ok |
| PEG>1.20、上記警告なし | trusted、expensive_or_moderate |

予想NPが不明・利益品質watchの場合はtrustedにしない。ただし、後から付いた警告で先に検出した極端なPEG／EPS警告を消さない。`peg_warnings` は配列とし、`peg_warning` は表示用の代表理由に留める。PEG<0.01をNoneに変えて極端値警告まで消してはならない。

**PEGは生値の単純加点ではないが、FE・レーンに影響する。** 「全スコアに未使用」という注記は禁止する。

### 13.4 FEの減点・決算補正

以下を1条件1回で適用し、内訳を保存する。

| 条件 | 減点 |
|---|---:|
| PS≤0.65または業種比PS≤0.72、かつ品質尺度Q9<6、かつPEG trusted/okではない | −14 |
| PER>120 | −6 |
| 90<PER≤120 | −3 |
| 必須財務欠損 | 1項目あたり−3.5、最大−18 |
| 年次比較不能 | −10 |
| 最新通期が400暦日超前の開示、または通期期末が550暦日超前 | −10。二重加算しない |
| Q9<5 | −15 |
| n=7かつk≤3 | −12 |

`Q9=quality_normalized_9`。未知をQ9=0に変えない。これらの減点で入力の信頼性が回復するわけではなく、必須データ不足は別途ゲートで止める。

年次情報が200日経過しただけの−4や、Standardで9項目揃わないことだけの減点は外す。

直近の**新規の通期実績発表**から30暦日以内の補正は既存に近い形で維持する。実績OP前年比が+15%以上なら+6、+5%以上なら+3、−15%以下なら−6、−5%以下なら−3、それ以外0。OP前年比が不明なら0。過去年度の訂正や、+92日の推定予定日ではこの補正を新たに発火させない。

```text
FE = clip(加点合計 − 減点合計 + 決算補正, 0, 100)
```

### 13.5 entry複合点とソフト圧縮【表示修正】

```text
entry_raw = clip(FE + 局面ボーナス − 乖離減点, 0, 100)
```

局面ボーナスはreclaim +8、bottom +4、above_near +3、extended −6、below_downtrend −14、unknown −3。上側の局面でd200>8%なら、`min(14, (d200−0.08)×65)` を減点する。

レーン別の圧縮基準値B：reclaim92、bottom85、weak78、watch75、extended65、light80、data_review70／severe55、forward62、trap45、excluded30、satellite72。新設の `financial_quality_watch` は55、`model_scope_review` は55、`earnings_watch` は75、`risk_blocked` は30とする。新設値は表示用の初期設定で、採用可否を左右しない。

```text
raw <= B : entry = raw
raw > B  : entry = min(100, B + (100-B)×(1-exp(-(raw-B)/24))×0.35)
```

これは**ハード上限ではない**。Bを超えてよい。変数を `entry_soft_cap_base` として出し、旧 `LANE_CAP_*` は互換名とする。データ不足の禁止条件をこのソフト圧縮だけで処理してはならない。

### 13.6 推奨順位点【基本維持】

```text
recommendation_score = 0.60×FE + 0.40×entry + adjustment
```

adjustmentは以下を原則1回ずつ適用する。

| 条件 | 補正 |
|---|---:|
| 予想NP増減率≤−20% | −12 |
| −20%超〜−10% | −6 |
| −10%超〜0%未満 | −2 |
| 有効な会社予想NP増減率がない | −6 |
| 予想対象期の不一致 | 追加−5 |
| 第8章で定義した利益品質watch | −8 |
| 根拠付きの会計リスクwatch | −10 |
| 根拠付きのガバナンスリスクwatch | −8 |
| 株主還元Q≥70、全成分・適用減点を評価済み | ＋3 |

重大リスクはこの点数ではなく前段ゲートで拒否する。未確認の監査状態をcleanとして加点しない。一方、外部監査未確認そのものを全銘柄一律の企業品質減点にも使わない。

FEとentryには共通のFE成分があるため、これは独立した二つの因子の60:40配合ではない。**その構造は初期比較のため維持し、純粋タイミング点への置換は別実験にする。**

### 13.7 legacy_totalとグレード

旧総合参考点は、固定した全体母集団のpercentileと修正済み入力を使って一度だけ計算する。

```text
legacy_total = clip(
  valuation_score + financial_score + resilience_score
  + technical_score + safety_score_scaled + sector_neutral_bonus
  - spec_penalty - per_penalty - data_penalty,
  0, 100)
```

内訳の配分（バリュエーション最大8、財務最大30、レジリエンス最大25、モメンタム最大14.3、安全性最大12、業種中立ボーナス最大4）は旧関数の形を維持する。詳細な旧区分点は[S1]の `_val_score_from_ps_vs_sector`、`_quality_score_from_piotroski`、`_growth_score_from_sales_cagr`、`_resilience_score_from_drawdown`、`_momentum_score_from_returns`、`_build_ranked` に固定し、最適化しない。

ただし、以下の差分を適用する。

1. 品質percentileは、全7項目を評価できた `summary_quality_7` の合格率で計算する。欠損の多い銘柄に有利なpercentileを作らない。
2. 原著9項目の実測と誤認する表示を除く。フォールバックの旧0〜9尺度へはQ9を使うが、接続用尺度と明示する。
3. 利益品質gapの仮定成分は診断用へ移し、固定0.70係数だけに依存する旧gap減点は無効にする。
4. 実際に採点へ使っていない補完項目数による減点は無効にする。構造的なPremium項目欠損も減点しない。
5. 信用・空売り等が未検証の間の旧安全性・投機性点は「利用可能入力内の参考値」。旧総合点は順位の最終補助に留める。
6. 日次と年率の混同、調整前価格によるDD等は、修正済み値へ置き換える。

`grade_raw` の旧境界は、70以上A+、62以上A、54以上B+、46以上B、未満Cを維持する。ただし旧版と同じ意味の成績ランクとは保証しない。**Standardという契約名だけのBキャップは廃止**する。

正式な `grade` は、必須データ不十分・対象モデル外の場合は `NR`（評価保留）。その他の旧グレード制限は、予想NP減益50%以上はC、30%以上はB、第8章の利益品質watch・根拠付き会計／ガバナンスwatchはB、確認済み重大リスクはCを上限として、最も厳しいものを採用する。単なる会計方針変更には適用しない。財務品質不合格や重大リスクはスコアが高くても候補にしない。A+は購入許可・安全保証・上昇確率ではない。

## 14. 必須フィルタ・レビュー状態・レーン

### 14.1 バリュエーション側Core【主要閾値を維持】

```text
instrument_type == stock
流動性の必要期間・価格基準が有効
avg_volume_30d >= 50,000株
adv_jpy_20d >= 300,000,000円
market_cap_jpy >= 50,000,000,000円
営業利益安定 == True
0 < PS <= 2.0
0 < per_conservative <= 60
必須財務項目の未解決欠損 == 0
summary品質の全7項目が比較可能（n=7）
```

これを満たすと `valuation_lane="core"`。品質の合格数kやエントリー時期は、次のレーン判定で確認する。企業の条件と買いタイミングを分ける既存構造を維持する。

PS/PERの条件だけでCore外となるものは `satellite_valuation` に残す。PSのみ有効な参考候補は `satellite_ps_only` とするが、赤字・予想損失を「PER欠損だからPSで救済」と扱わない。欠損・未解決データによる不適格をSatelliteへ迂回させない。

業種比PS≤1.10はFEの区分点であり、この初期版では新しいCore必須条件にはしない。PER60は割安の証明ではなく、従来の粗い上限である。

### 14.2 データレビューの区別【Standard対応】

| 状態 | 例 | 扱い |
|---|---|---|
| 正常な評価範囲制約 | summary_only、gross margin対象外、current ratio対象外 | `structural_limitations` に記録。レビュー落ち・減点なし |
| light | 時価総額が開示株数代理、業種ベンチマーク不足、採用に使う値の未解決の確認事項 | 値は参考に残すが正式新規候補に混ぜない |
| medium | 品質7項目の追加欠損、年次履歴不足、未解決の比較可能性 | `data_review`、新規候補不可 |
| severe | コード衝突、通貨不一致、壊れたキャッシュ、必須価格欠損、時点不整合、古すぎる通期 | `data_review` または実行停止、新規候補不可 |
| 企業の品質不合格 | 全項目観測済みだが低得点、CFO赤字等 | `financial_quality_watch`。データ欠損とは呼ばない |
| 外部情報の未確認 | ガバナンス未確認、正常に取得した決算予定APIに当該予定なし | `pretrade_check_required`。企業点の自動減点とは分離 |

必須APIをまだ収集していない状態を、正常に取得した結果の「当該銘柄の報告なし」と混同しない。

診断専用の上昇余地、3年CAGR、株主還元Q、会社予想などが未取得というだけでは、data_review_levelを上げない。それぞれNone・未評価理由を表示し、定義済みの加減点だけ適用する。新規候補に必要な入力の基準不明や、必須比較項目の欠損だけを対応するゲートで止める。

### 14.3 レーン判定の優先順位

まず全ての理由フラグを計算し、その後で下記の順序で主レーンを確定する。早期returnにより、他の重大理由が記録から消えてはならない。

| 順序 | 判定 | 主レーン |
|---:|---|---|
| 1 | 普通株でない／無効コード | `excluded` |
| 2 | 根拠付き重大リスクあり | `risk_blocked` |
| 3 | コード・価格・時点などモデル共通の必須データ不整合／必要レジーム不明 | `data_review` |
| 4 | 一般事業会社モデルの対象外 | `model_scope_review` |
| 5 | 当該モデルに必要な財務・比較データにmedium/severeあり | `data_review` |
| 6 | 極端PEGまたは代理EPS急増と、営業利益の悪化が併存 | `cyclical_value_trap` |
| 7 | 有効な会社予想の30%以上減益・予想損失 | `forward_downgrade_watch` |
| 8 | 営業利益安定False、Q1/Q2不合格、またはn=7かつk<5 | `financial_quality_watch` |
| 9 | 価格の下降拒否 | `excluded`（理由付き） |
| 10 | 流動性・規模の確定的不合格 | `excluded` |
| 11 | バリュエーションがCore外、データ・基本財務は有効 | 対応する `satellite_*` |
| 12 | lightの未解決事項あり | `data_review_light` |
| 13 | 決算blackout | `earnings_watch` |
| 14 | 過熱、d200>15% | `extended_above_ma200` |
| 15 | reclaim条件・財務品質・FE閾値を満たす | `ma200_reclaim_core` |
| 16 | reclaim品質合格、60≤FE<reclaim閾値 | `weak_reclaim_watch` |
| 17 | bottom条件・品質・FE≥75、risk_offでない | `bottom_reversal_core` |
| 18 | データ有効・FE≥60だが転換の採用条件未達 | `watch_fundamental_core` |
| 19 | その他 | `excluded`（理由付き） |

業種の適用範囲は、一般事業会社用のOP・CFO・負債比率を評価する前に確定する。対象外の金融業について、当該モデルで非該当の項目を「必須財務欠損」として先に落とさない。

`cyclical_value_trap` の条件は、`0<PEG<0.30` または代理EPS成長>80%に加え、営業利益安定Falseまたは実績OP前年比<0が併存する場合。単独の急成長だけでtrapと断定しない。

`reclaim_quality` は第7章のn=7、k≥5、Q1/Q2、営業利益安定条件に加え、`extremely_low_possible_oneoff` と `eps_growth_too_high_oneoff_risk` のいずれもないこと。`bottom_quality` はこれにk≥6、21日リターン>0、直近10営業日で60日安値更新なしを追加する。警告配列の全体を検査し、表示用の代表警告が変わっても禁止条件は失われない。

reclaimのFE閾値は通常70、risk_offでは75。bottomはrisk_off時には新規採用せず、条件が良くてもwatchへ置く。

`above_ma200_near` はデータと基本条件が有効でFE≥60ならwatchへ置く。`buy_timing_gate=True` なのに対応分岐がなくexcludedへ落ちる旧挙動を修正する。

### 14.4 新規候補の最終契約

```text
eligible_new_entry =
    core_candidate
    AND candidate_lane in {ma200_reclaim_core, bottom_reversal_core}
    AND data_review_level == none
    AND not earnings_blackout
    AND no_confirmed_severe_risk
    AND common_asof_valid
    AND regime_known
```

`eligible_new_entry=True` は定量スクリーニング通過であって、証券会社への注文指示ではない。`pretrade_check_required` と未確認の上昇余地を表示する。本スクリーナーは自動注文を実行しない。

### 14.5 表示上の優先順位

買い候補一覧はeligibleのみ。reclaim→bottom、各レーン内は推奨順位点の降順とする。0銘柄なら「候補なし」。監視銘柄でTop10を埋めない。

監視を含む全体表示では、既存に近い優先番号を保つ。

```text
10 reclaim / 20 bottom / 30 light+reclaim / 40 fundamental_watch
45 weak_reclaim / 48 earnings_watch / 50 extended
55 financial_quality_watch / 58 forward_downgrade / 60 data_review
65 lightその他 / 70 cyclical_trap / 80 satellite
90 model_scope_review / 990 risk_blocked / 999 excluded
```

同じティア内では `recommendation_score → FE → entry → legacy_total → code`。`watch_fundamental_core` の二次キーだけはFEを優先する。最終codeは安定した同点順序のためで、投資上の優先性を意味しない。

## 15. 仕手株回避・需給診断

### 15.1 判定可能な範囲

本版は、仕手筋の存在・株価操縦を断定する検出器ではない。レポートの「仕手」は **「投機性・需給リスク参考値」** に改める。

価格、流動性、ボラ、信用残、企業業績から異常を観測するが、取得不足の点数0を「安全」と表示しない。`spec_inputs_coverage`、`spec_model_scope`、元データの基準日・公表日を併記する。

### 15.2 信用残【修正】

`/markets/margin-interest` の `LongVol`／`ShrtVol` を使う。売残>0なら信用倍率を計算する。売残0・買残>0は有限の小さな倍率に置き換えず、`ratio_state="zero_short_balance"` とする。両方0も正常な低倍率に偽装しない。[R10]

信用残は基準日と公表日が異なる。基準日の金曜日時点で、翌週公表のデータを知っていたことにしてはならない。過去の利用可能日時が確定できなければ、その指標を過去順位から外す。[R6]

**2026-09-28に新仕様の提供開始予定が公式に記載されている。2026-09-11現在の旧週次スキーマをそのまま将来も固定適用しない。** 移行日前後はスキーマ・頻度・時点のアダプタを分け、稼働時に再確認する。[R10]

### 15.3 空売り報告【修正】

`/markets/short-sale-report` の `DiscDate`、`CalcDate`、報告主体・運用財産、`ShrtPosShares`、`ShrtPosToSO` 等を保存する。複数主体・複数日の行をそのまま足したり、6行前を5週間前と扱ったりしない。[R11]

初期版は報告イベントの診断として表示し、銘柄全体の「5週空売り残増減率」を自動採点へ接続しない。主体名だけでは同一性が確定しないケースや報告対象外残高を含むため、合計を算出する場合も「公表対象の観測値」と明示する。報告がないことは総残高ゼロを意味しない。

### 15.4 初期運用と検証専用の境界

既存の価格・ボラ・流動性の投機性成分は、修正済み入力で比較診断に残す。配当状態を使う場合は同じ対象期・分割基準で生成して実際に引き渡す。定義できていない「急騰後停滞日数」はNoneとし、0で渡さない。

急騰日の集中度、売買代金の持続増加、決算による裏づけ等の新しい投機性識別は、第16章の検証専用項目とする。初期の新規不採用は、流動性不合格・財務不合格・過熱・明確なリスク等の定義済み条件で行い、未検証の点数に新たな禁止閾値を足さない。

## 16. 残存上昇余地と上昇の持続性【検証専用】

### 16.1 初期版での位置づけ

上昇余地は戦略の重要な評価軸である。ただし、バグ修正と新しい価格予測モデルの採用を同時に行うと、どの変更が効いたか分からない。本版では、以下を**計算・表示・保存する診断列**とし、`recommendation_score` の重みやCore昇格条件にはまだ加えない。

```text
UPSIDE_MODE = diagnostic
PERSISTENCE_MODE = diagnostic
```

これらの列が存在するだけで「長期上昇を予測できる」とは主張しない。最終的な個別銘柄検討では、上昇余地の根拠・未確認事項を確認する。

### 16.2 機械的に計算できる割安解消余地

```text
rerating_space_ps = sector_ps_median / PS - 1
```

これは「自社のPSが業種中央値へ変化した場合の倍率差」であり、**適正株価までの上昇余地ではない**。自社と他社の利益率・成長率・資本構成が違うため、倍率差が解消される保証はない。業種基準が不明ならNone。負の値も0へ丸めず残す。

同時に以下を出す。

```text
net_profit_margin          = NP / Sales
operating_margin           = OP / Sales
cfo_margin                 = CFO / Sales
normalized_np_3y           = 比較可能な連続3期NPの中央値
per_normalized_np_3y        = market_cap_jpy / normalized_np_3y（分母>0のみ）
forward_np_change          = 有効な予想NP / 実績NP - 1
```

`normalized_np_3y` は過去中央値であり、将来の持続可能利益を推定済みとは呼ばない。3期すべてを使い、都合の悪い赤字期を落として中央値を作らない。

### 16.3 仮定付きの株価シナリオ

シナリオを出す場合は、想定純利益・想定PER・対象期間・根拠を明示する。自動的に「PER15倍」「業種最高値へ回帰」等を埋めない。

上場株式数が一定という仮定のもとで、時価総額基準の主PERと整合させる。

```text
scenario_value = scenario_np × scenario_per
scenario_price = current_price × scenario_value / current_market_cap
upside_ratio   = scenario_price / current_price - 1
```

`scenario_np` は利益額、`scenario_per` は倍率。弱気・基準・強気は別々の入力とし、楽観ケースだけを表示しない。予想増資・消却がある場合は株数一定の仮定を使わず、対応モデルがなければ価格をNoneにする。

保存列：`scenario_horizon`、`scenario_np_*`、`scenario_per_*`、`scenario_price_*`、`upside_*`、`scenario_assumptions`、`scenario_source`、`scenario_created_at`、`scenario_confidence`。

確率を推定していない場合は、期待値 `EV` を計算しない。上昇余地30%と期待リターン30%は別である。配当を加えた総リターンを表示する場合は、分割基準・期間・実績／予想を合わせ、再投資や税金の仮定を明示する。

### 16.4 上昇持続性の診断

初期版は総合点を作らず、次を観測する。

| 診断列 | 定義・留意点 |
|---|---|
| `positive_cfo_years_3y` | 連続3期でCFO>0の期数。欠損は期数から除いて満点換算しない |
| `cumulative_cfo_to_np_3y` | 3期CFO合計／3期NP合計、NP合計>0のみ |
| `op_margin_change_yoy` | 最新OPマージン−前期OPマージン。倍率ではなく比率差 |
| `np_growth_actual`／`forward_np_change` | 実績改善と予想改善を分ける |
| `return_rel_topix_63d` | `(1+銘柄63日リターン)/(1+TOPIX63日リターン)-1` |
| `ma200_cross_count_60d` | 60営業日のMA200上抜け・下抜け回数。往復の多さを診断 |
| `turnover_persistence` | 直近20日のVa中央値／その前60日のVa中央値。比較期間と欠損数を保存 |
| `positive_return_top3_share_63d` | 63日の正の日次対数リターン合計に占める上位3日の割合。正の合計が0ならNone |

最後の指標は「上昇が少数日の急騰に集中しているか」の診断であり、仕手性の証明ではない。決算再評価による本物の急騰もありうるため、単独で除外しない。

### 16.5 採用と保有継続を分ける

MA200クロスから20営業日を過ぎても、既保有株の自動売却条件にはしない。転換後に値上がりして新規購入の余地が小さくなった場合も、既保有を直ちに売る判断とは別である。

本書は**新規候補選別の正本**であり、出口戦略は未確定。固定利確、部分利確、トレンド追随を比較する検証は、同じ銘柄選別条件で別々に行う。

## 17. 推奨ストップ・数量の扱い

### 17.1 初期運用では自動数量提案を無効化【修正＋初期運用方針】

```text
POSITION_SIZING_ENABLED = false
portfolio_capital_jpy   = None
risk_budget_ratio      = None
recommended_shares     = None
```

ユーザーの運用資金・許容損失を固定1,000万円等で仮定しない。未知のボラを0.022で補い、リスク調整済み数量のように見せない。監視・要確認・除外レーンへ新規配分を推奨しない。

### 17.2 ストップ参照値

既存方式は**比較用のストップ参照値**として、単位を修正して残せる。

```text
reclaim：MA200を当日実株価基準へ換算した値 × 0.95
bottom ：実株価 × (1 − clip(2.5×vol_daily_20d, 0.05, 0.18))
```

実価格とMAの基準が揃わなければNone。ボラ不明ならbottomの参照値はNone。5%下限は現行コードの実計算を採用した値で、旧コメントの8%とは異なる。[S1:_build_ranked]

`stop_reference_price`、`stop_distance_ratio`、`stop_method` を出し、約定保証や損失上限とは表示しない。翌日のギャップやスリッページを考慮していない。

### 17.3 利確値

従来の一律+20%／bottom+25%／extended+12%を、企業価値に基づく `suggested_take_profit` として推奨することはやめる。互換検証に必要なら `legacy_tp_reference` に隔離する。正式の `suggested_take_profit` は、出口戦略が別途定義されるまでNone。

仮定付きシナリオ価格とストップ参照値から `reward_to_risk_reference` を出す場合、値は実現確率・期待値ではない。現在価格より低いシナリオ価格も正しく負の余地として表示する。

### 17.4 将来、数量を有効にするための契約

資金、許容損失率、利用可能現金、1銘柄上限、ロット単位を明示設定した場合のみ計算する。基本形は次のとおり。

```text
q_risk   = capital × risk_budget_ratio / (entry_price − stop_price)
q_weight = capital × lane_max_weight / entry_price
q_cash   = available_cash / entry_price
q_final  = ロット単位で切り下げた min(q_risk, q_weight, q_cash, 任意の流動性上限)
```

entry>stop>0を要求し、ロット未満なら0。初期の1銘柄上限は既存のreclaim8%・bottom5%を上限値として残せるが、これ自体を最適と主張しない。複数候補へ同じ現金を重複割当てしない。

これは損切り距離基準の数量計算である。旧 `POSITION_TARGET_ANNUAL_VOL / stock_vol` を一律上限へクリップする式は廃止する。ポートフォリオの年率リスクを管理するには相関と既存保有を含む別設計が必要で、本式をその代用と呼ばない。

### 19.2 CLIの互換

既存の `--phase collect / collect_all / analyze / single / interactive / fields-audit` を維持する。`--phase single` でも、全体分析と同じマスタ・業種統計・情報締切を使う。[S1:main]

## 21. 適用順序と実運用前の確認

### 21.1 実装の順番

**第一段階：入力の正しさ**  
コード、商品分類、セクター、調整価格、時価総額単位、財務期間、予想解決、Eq/自己資本の区別、配当期間を修正する。

**第二段階：判定の整合性**  
Standard品質7項目、欠損と品質不合格の分離、過熱優先、blackout、Coreとエントリーの接続、同一母集団採点を実装する。

**第三段階：運用の再現性**  
無通信分析、manifest、immutable履歴、空出力、入力監査、未確認データの表示を実装する。

**第四段階：前方観測**  
バグ修正後の基準版を固定して運用結果を記録し、上昇余地・持続性を診断する。新指標を順位へ反映する変更は別バージョンで行う。

### 21.2 運用開始判定

受入テストのうち実装範囲に該当する必須テストが合格し、既知の重大誤計算が残っていないこと。実データでは、Standardの生レスポンスについて、MktCap・ExRT・ProdCat、年次財務、予想、配当、信用データの保存・変換を確認する。

旧版と新版で候補・スコアが変わった場合は、コード修正、Standard再定義、初期運用方針、データ更新を切り分ける。順位がよく見えることを修正成功の根拠にしない。

### 21.3 期待値の検証

初期評価窓は63・126・252営業日を観測候補とし、保有期間の最適値とはみなさない。

平均・中央値リターン、TOPIX超過リターン、最大逆行、上昇継続、最大順行、売買代金、業種集中を、reclaimとbottomで別集計する。手数料・スリッページ・翌日ギャップを明示する。

同じ銘柄の同じ転換を毎日独立標本として数えない。シグナル期間を一つのイベントとして管理し、銘柄・時期の重複による見かけの標本数を増やさない。

採用条件の効果を測るときは退出ルールを揃える。退出ルールを比較するときは銘柄選別を揃える。新しい上昇余地指標は、修正済み基準版に一つずつ追加して比較する。
